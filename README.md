# BrandForge AI

Agentic SaaS platform for AI-driven marketing and branding: brand kits, campaign
concepts, social posts, and landing pages — generated by AI agents, reviewed by humans.

**Status:** Phases 1–3 (foundation + full auth + agentic engine). Phases 4
(landing-page builder) and 5 (billing/teams) are planned — see `docs/`.

**Owner:** Jon Peciña Iturbe · <jpecina@gmail.com>

## Architecture

```
                    ┌──────────────────────────────────────────────┐
                    │  VERCEL (presentation only)                   │
                    │  apps/web — React + TS SPA (PWA)              │
                    │  The browser NEVER calls OpenRouter.          │
                    └───────────────┬──────────────────────────────┘
                                    │ HTTPS  /brandforge/api/*
                    ┌───────────────▼──────────────────────────────┐
                    │  ORACLE (business / data / security)         │
                    │  Ubuntu 24.04 aarch64 · 143.47.63.169        │
                    │  nginx (jpecina.duckdns.org, mi-gps block)   │
                    │       │                                      │
                    │       ├─ Fastify API  127.0.0.1:3013 ─┐      │
                    │       ├─ Postgres 15                  │      │
                    │       └─ Worker (job queue)           │      │
                    │              │                        │      │
                    │              └─► OpenRouter (inference, Phase 3)
                    └──────────────────────────────────────────────┘
```

- **Frontend** (`apps/web`): React + TypeScript SPA, bilingual EN (default) + ES,
  PWA, `@vercel/analytics` in code (enabled in the Vercel dashboard by the owner).
- **API** (`apps/api`): Fastify + Node 24, session-cookie auth (Argon2id), RBAC,
  rate limits. Listens on **127.0.0.1:3013** (reserved BrandForge port).
- **Database** (`packages/database`): Postgres 15 + Drizzle ORM, SQL migrations.
- **Worker** (`apps/worker`): background jobs (Phase 3+: AI generation pipeline).
- **Inference**: OpenRouter — called only from API/worker, never from the browser.

Details: `docs/ARCHITECTURE.md` · Decisions: `docs/adr/`

## Quickstart (local)

Prerequisites: Node 24, Docker + Compose plugin.

```bash
# 1. Environment
cp .env.example .env
#    -> set POSTGRES_PASSWORD (and keep DATABASE_URL in sync)

# 2. Start postgres + api (+ worker)
docker compose -f infrastructure/docker/docker-compose.yml up -d --build

# 3. Migrate + seed the demo brand (Café Aroma, Bilbao)
npm run db:migrate
npm run db:seed

# 4. Frontend
cd apps/web && npm install && npm run dev
```

Open http://localhost:5173 and sign in with the **local demo account**:

> **demo@brandforge.local / Demo2026!**
> ⚠️ LOCAL-ONLY demo credentials. They are baked into the seed for development and
> must never exist in production (the seed refuses to run with `NODE_ENV=production`
> unless explicitly overridden — see `docs/adr/0005-demo-isolation.md`).

Regenerate the demo PNG assets any time (idempotent, needs no network):

```bash
node tools/generate-demo-assets.mjs
# sharp lives in an isolated /tmp tool env, NOT in the monorepo deps
```

## Scripts (root)

|------------------|-----------------------------------------------|
| `npm run build`  | Build all workspaces                          |
| `npm run test`   | Run all workspace tests                       |
| `npm run typecheck` | Type-check all workspaces                  |
| `npm run db:generate` | Generate a Drizzle migration             |
| `npm run db:migrate`  | Apply migrations                         |
| `npm run db:seed`     | Seed demo data (Café Aroma)              |

## Testing notes

- Every workspace ships its own tests; `npm run test` runs them all.
- Auth is covered by `apps/api` tests: registration, email verification (maildir in
  dev), login, session rotation, logout-everywhere, password reset, RBAC matrix.
- The seed script is idempotent: re-running `npm run db:seed` upserts the Café Aroma
  demo project and warns (does not fail) when `seed-assets/` is empty.
- Demo-asset PNGs are verified by `tools/generate-demo-assets.mjs` itself, which
  asserts output dimensions via sharp metadata after each render.
